ឧបករណ៍ AI កាន់តែមានសមត្ថភាព។ ប៉ុន្តែកាកាន់តែមានសមត្ថភាព អ្នកប្រើកាន់តែក្លាយជាត្រង់ច្រំ — ឆ្លងកាត់ context ពី session មួយទៅ session មួយទៀត ចងចាំថា tab មួយកំពុងធ្វើអ្វី ហើយវេលាប់ផ្ទាំងច្រើនដែលដំណើរការភ្នាក់ងារច្រើនលើគម្រោងតែមួយ។ នៅថ្ងៃមួយ អ្នកមើលទៅអេក្រង់ ហើយដឹងច្បាស់៖ អ្នកមិនដឹងទេថា ភ្នាក់ងារទាំងនេះកំពុងធ្វើអ្វី។

មិនមែនកូដទេ — កូដនៅទីនោះ។ ប៉ុន្តែ context បាតបោយ។ ហេតុអ្វីពួកគេជ្រើសរើសយកវិធីនោះ។ សព្វវិធីអ្វីដែលពួកគេរៀបចំធ្វើបន្ទាប់។ អ្វីដែលពួកគេបានព្យាយាម ហើយបរាជ័យ។

នោះគឺជាចំណុចបកប្រែ។ មិនមែន "ខ្ញុំត្រូវការ AI ដែលល្អជាង" ទេ។ ប៉ុន្តែ៖ ខ្ញុំត្រូវការគ្រប់គ្រង AI ដូចដែលខ្ញុំគ្រប់គ្រងក្រុមមួយ។

## អ័ក្សត្រឹមខុស

![គម្រោង-កណ្តាល _vs_ ភ្នាក់ងារ-កណ្តាល](/blog/why-we-built-phneakngar/wrong-axis.svg)

ឧបករណ៍មួយៗដែលអ្នកប្រើ សុទ្ធតែរៀបចំជុំវិញគម្រោង។ មួយគម្រោង មួយភ្នាក់ងារ ច្រើនបង្អួរ context។ គម្រោងតែមួយត្រូវការអ្នកគ្រងគម្រោង អ្នកសរសេរកូដ អ្នកពិនិត្យ និងអ្នកផ្សព្វផ្សាយ។ តួនាទីបួន — ប៉ុន្តែឧបករណ៍ផ្តល់តែភ្នាក់ងារមួយ។ ដូចនេះអ្នកបើកផ្ទាំងច្រើន ហើយក្លាយជាសារឆ្លងកាត់រវាងបង្អួរ context ផ្ទាល់ខ្លួន។

នោះគឺជាកណ្តៀរ៖ ឧបករណ៍រៀបចំជុំវិញកូដ។ ប៉ុន្តែការងាររៀបចំជុំវិញមនុស្ស។

នៅពេលមើលឃើញ អ្នកមិនអាចមិនមើលឃើញទេ។ រៀបចំជុំវិញភ្នាក់ងារ មិនមែនជុំវិញគម្រោងទេ។ ផ្តល់តួនាទី អំណី និងវិធីទំនាក់ទំនងឲ្យភ្នាក់ងារមួយៗ។ ទុកឲ្យពួកគេប្រមូល context ឆ្លងកាត់ថ្ងៃ និងសប្តាហ៍ — មិនមែនតែក្នុង session តែមួយទេ។

## ស្រទាប់ Context ដែលបាត

![អ៊ីមែលជាំណីជាប់រហូត](/blog/why-we-built-phneakngar/email-memory.svg)

ភ្នាក់ងារដែលគ្មាន context រួបរំ គឺតែជាស្វ័យប្រវត្តិការដែលថ្លៃ។ គម្រោងមួយៗចាប់ផ្តើមពីសូន្យ។ ការប្រគល់មួយៗត្រូវការឲ្យអ្នកពន្យល់ម្តងទៀត។ Context នៅក្នុងក្បាលអ្នក — ដែលមានន័យថាអ្នកនៅតែជាត្រង់ច្រំ។

អ្វីដែលភ្នាក់ងារត្រូវការពិតប្រាកដ គឺជាមជ្ឈមណ្ឌល context។ ស្រទាប់ជាប់រហូត ដែលការប្រាស្រ័យទាក់ទង សេចក្តីសម្រេច និងខ្សែការណ៍មួយៗ នៅរស់ឆ្លងកាត់ថ្ងៃ និងសប្តាហ៍។ នៅពេលអ្នកគ្រងគម្រោងប្រគល់ការទៅអ្នកសរសេរកូដ context នោះគួរជារបស់ពួកគេទាំងពីរជាប់រហូត។ សប្តាហ៍ក្រោយ ពួកគេនៅតែដឹងអ្វីបានកើតឡើង។ អ្នកមិនពន្យល់ម្តងទៀត។ មិនឆ្លងកាត់ចម្លង។ មិនបាតខ្សែការណ៍។

ក្នុង ភ្នាក់ងារ ស្រទាប់ context នោះគឺអ៊ីមែល។ អាស្ម័ន ជាប់រហូត និងមាន contextតាមរចនាសម្ព័ន្ធ។ អ្នកនិយាយជាមួយភ្នាក់ងារដូចនិយាយជាមួយសហការី។ ប៉ុន្តែខាងក្រោម មានអំណីរួបរំដែលធ្វើឲ្យគម្រោងទាំងអស់សាបជួរ — មិនរលត់បាតទេ។

ចំណុចប្រទាក់គឺស្គាល់ស្រី។ សមត្ថភាពមិនស្គាល់ទេ។

## មនុស្សមួយ ភ្នាក់ងារមួយពាន់

![មនុស្សមួយ ភ្នាក់ងារមួយពាន់](/blog/why-we-built-phneakngar/agent-company.svg)

សំណួយពិតប្រាកដមិនមែន "ភ្នាក់ងារមួយអាចធ្វើអ្វីបាន" ទេ។ គឺ "មនុស្សមួយអាចគ្រប់គ្រងភ្នាក់ងារប៉ុន្មាន"។ ចម្លើយគឺមួយពាន់ — បើអ្នកមានប្រព័ន្ធត្រឹមត្រូវ។ ភ្នាក់ងារ កំពុងកសាងប្រព័ន្ធនោះ។

មិនមែនបង្អួរសន្ទនាល្អជាងទេ។ គឺជាកម្មវិធីបង្កើតក្រុមហ៊ុនភ្នាក់ងារ។

> គោលដៅសាមញ្ញ៖ គិតតិច មិនមែនគិតច្រើនទេ។ ប្រគល់ភារកិច្ច ហើយភ្លេច។ ភ្ញាក់ឡើង ហើយភ្នាក់ងារបានធ្វើការរួច — ហើយអ្នកអាចតាមដានច្បាស់ថាហេតុអ្វី។

ខួវកាបានស្រាល។ នោះគឺជាចំណុចទាំងអស់។

## កសាងក្រុមហ៊ុនភ្នាក់ងាររបស់អ្នក

ភ្នាក់ងារ គឺបើកចំហ។ ដំណើរការលើម៉ាស៊ីនរបស់អ្នក។ ទិន្នន័យនៅជារបស់អ្នក។ តាំងភ្នាក់ងារដំបូងក្នុងពីរនាទី ផ្តល់តួនាទី ហើយទុកឲ្យពួកគេស្រាយបញ្ហាដោយខ្លួនឯង។ បន្ទាប់មកបន្ថែមមួយទៀត។ ហើយមួយទៀត។
